# 坐标导入与封装匹配

## 1. 支持的格式

| 格式 | 识别方式 | 说明 |
| --- | --- | --- |
| 通用坐标表 | 默认 | CSV / TSV / 分号 / 空白分隔；表头别名识别 |
| KiCad `.pos` | 文件含 `### Module positions` 或 `# Ref ... PosX PosY` | 含底面 X 取反与 `180 - rot` 约定 |
| OpenPnP 板文件 | `<openpnp-board>` | 读 `placement` 与 `fiducial` 元素 |
| KiCad 7 CSV | 通用坐标表 | 表头 `Ref,Val,Package,PosX,PosY,Rot,Side` |

暂不支持：Gerber / ODB++ / IPC-2581 / Altium 二进制 / Eagle `.brd` 直接解析。

## 2. 导入流程

```
选择文件
  → 识别格式（detect_format）
  → 读表头（header_preview）自动映射列
  → 向导里确认：列映射 / 单位 / 角度补偿 / 镜像 / 交换 XY / 偏移
  → 解析预览（前 10 行）
  → 替换或追加到产品
  → 元件落库 + 封装自动匹配
```

### 2.1 列映射

必需：位号、X、Y。可选：旋转角、元件名称、封装、板面、跳过标记、单位。

表头别名示例（不区分大小写，忽略空格/下划线/括号）：

| 字段 | 别名 |
| --- | --- |
| 位号 | `Designator` `Ref` `Reference` `ComponentRef` `位号` |
| X | `Mid X` `PosX` `CenterX` `X (mm)` `坐标X` |
| Y | `Mid Y` `PosY` `CenterY` `Y (mil)` `坐标Y` |
| 旋转 | `Rotation` `Rot` `Angle` `角度` |
| 元件 | `Comment` `Value` `Val` `Part` `元件` `规格` |
| 封装 | `Footprint` `Package` `Pattern` `Case` `封装` |
| 板面 | `Layer` `Side` `板面` `层` |
| 跳过 | `DNP` `Skip` `DoNotPlace` `不贴` |

识别不到表头时会在向导里提示手动映射。

### 2.2 单位

- 表头里带 `(mil)` / `(inch)` / `(mm)` 自动换算；
- 也支持显式选择单位；
- KiCad `.pos` 会读 `## Unit = ...`；
- 内部统一 mm。

### 2.3 坐标变换

按顺序：交换 XY → 镜像 X/Y → 底面 X 取反（可选）→ 角度补偿 → 平移偏移。
KiCad `.pos` 的底面约定自动处理（X 取反、`180 - rot`），不需要再手动镜像。

### 2.4 常见坑

| 现象 | 原因 |
| --- | --- |
| 整板上下颠倒 | 板原点在左上角 vs 左下角，用「镜像 Y」或调板原点 |
| 角度整体差 90° | EDA 以 0° 为垂直方向，用「角度补偿」 |
| 底面元件位置镜像 | 底面坐标是“翻板后”视角，用「底面 X 取反」 |
| mil 数值巨大 | 表头没写单位，手动选 mil |
| 位号重复 | 只保留最后一条并给出警告 |

## 3. 封装匹配

### 3.1 为什么需要

EDA 导出的封装名五花八门：`R-0603_1608Metric`、`C0603`、`SOP8`、`SO-8`、
`QFN32_5x5`。元件库需要统一的封装 ID 才能选吸嘴、套视觉参数、算尺寸。

OpenPnP 本身**没有自动封装匹配**（只有 `id.toUpperCase()` 精确查找），
所以这里是按物料命名规律自建的匹配器。

### 3.2 归一化

1. 大写、去括号注释、去 `Metric/Imperial` 后缀；
2. 分隔符统一为 `-`；
3. 去元件前缀：`R_0603` → `0603`、`C0805` → `0805`、`Capacitor-0805` → `0805`；
4. 去尺寸后缀：`QFN32_5x5` → `QFN32`；
5. 公制码映射：`1608` → `0603`、`1005` → `0402`、`3216` → `1206` …

> `0603` 存在“英制 0603（1.6×0.8）”与“公制 0603（0.6×0.3）”重名。
> 本项目按行业习惯把裸 `0603` 解释为**英制**；公制请写 `1608` 或 `0603Metric`。

### 3.3 同义名

内置约 40 组，例如：

- `SOIC-8` ↔ `SOIC8` / `SO-8` / `SOP-8`
- `QFN-32` ↔ `QFN32` / `VQFN-32`
- `SOT-23-5` ↔ `SOT23-5` / `SOT25`
- `LED-0603` ↔ `LED0603` / `LED-1608`
- `USB-C-16P` ↔ `USB-C` / `TYPE-C-16P`

### 3.4 打分

| 情况 | 分数 |
| --- | --- |
| 归一化后与任一别名完全相同 | 1.00 |
| 同义名归一后相同 | 0.96 |
| 名称相似（difflib） | 0.72–0.85 |
| 仅有本体尺寸吻合（±35% 内） | ≤ 0.72 |
| ≥ 0.92 | 判定“确认”，导入时自动套用尺寸/吸嘴/视觉 |
| 0.72–0.92 | 判定“疑似”，只记录不套用 |
| < 0.72 | 未知，提示去封装库处理 |

名称匹配 ≥ 0.9 时不再用尺寸修正，避免“名字全对但尺寸有偏差”被降级。

### 3.5 使用

- 导入时自动匹配，并报告确认/疑似/未知数量；
- **封装库** 页可输入任意封装名做单条匹配，也可对已导入元件做批量匹配；
- 匹配结果写回 `Component.package_id` 与 `match_score`，尺寸/吸嘴/视觉按确认结果套用。

## 4. 封装库

`midpnp/data/packages.json` 内置 50+ 常见封装（片式、SOT、SOIC、TSSOP、QFN、LQFP、
LED、晶振、电感、连接器、基准点…），字段：

```jsonc
{ "id": "PKG-0603", "name": "0603", "aliases": ["1608", "R0603"],
  "category": "chip", "length_mm": 1.6, "width_mm": 0.8, "height_mm": 0.8,
  "pin_count": 2, "pad_rows": 1, "pad_width_mm": 0.8, "pad_height_mm": 0.9,
  "nozzle": "N1", "vision_mode": "None", "tags": ["passive"] }
```

`pad_rows`：`1` 两端/单排、`2` 双列、`4` 四边、`0` 自定义（显式 `pads`）。
未显式给焊盘时按本体与引脚数推导近似焊盘，用于绘图与视觉演示。

用户修改保存在 `<数据目录>/packages.json`，同 ID 覆盖内置项，不改安装目录。
